# Deployment

ExamGrid ships as two images built by CI and published to GitHub Container Registry on
every push to `main`:

| Image | Contents |
|---|---|
| `ghcr.io/n3h4a/examgrid-api` | Spring Boot API (layered jar, JRE 21, non-root) |
| `ghcr.io/n3h4a/examgrid-web` | React build served by Nginx, which also proxies `/api` |

They need PostgreSQL 16 and Redis 7. Pick one of the two paths below.

## Option A: one VM with Docker (recommended for a college)

A 2 vCPU / 4 GB VM is plenty for a few thousand students.

1. Point a DNS name (e.g. `exams.example.edu`) at the VM and open ports 80 and 443.
2. Install Docker, then:
   ```bash
   git clone https://github.com/n3h4a/ExamGrid.git /opt/examgrid && cd /opt/examgrid/deploy
   cp .env.example .env && nano .env      # DOMAIN, secrets, admin password
   docker compose -f docker-compose.prod.yml --env-file .env up -d
   ```
3. Caddy obtains a TLS certificate automatically. Open `https://<DOMAIN>` and sign in with the
   bootstrap admin, then create a second exam-cell account (publishing needs two people).

The GHCR packages must be public, or the VM must `docker login ghcr.io` first. On GitHub:
*Packages → examgrid-api / examgrid-web → Package settings → Change visibility*.

**Upgrades:** `docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d`.
Flyway migrates the schema on start-up. Pin `EXAMGRID_VERSION=sha-<commit>` for repeatable deploys.

**Backups:** `deploy/backup.sh` writes a `pg_dump` and a tarball of uploads and PDFs and keeps 14
days. Schedule it with cron. Redis holds only derived data and needs no backup.

**Network layout:** only Caddy publishes ports. Caddy discards client-supplied
`X-Forwarded-For`; Nginx trusts it only from the private network and overwrites it upstream,
so the per-IP rate limit cannot be spoofed.

## Option B: Render (free tier, for a public demo)

1. Fork or use this repository, then in Render choose **New → Blueprint** and select it.
   `render.yaml` creates PostgreSQL, Key Value (Redis), `examgrid-api` and `examgrid-web`.
2. Enter a password for `EXAMGRID_BOOTSTRAP_ADMIN_PASSWORD` when prompted. The JWT secret is
   generated by Render.
3. Open the `examgrid-web` URL. The blueprint enables the synthetic demo university.

Free-tier caveats: services sleep when idle (the first request takes about a minute), the free
PostgreSQL instance expires after a period set by Render, and the API's disk is ephemeral, so
generated PDFs disappear on redeploy (publishing again regenerates them). Use a paid plan with
a persistent disk mounted at `/data` for real use.

## Configuration reference

| Variable | Required | Purpose |
|---|---|---|
| `EXAMGRID_JWT_SECRET` | yes | HS256 signing secret, 32+ characters |
| `EXAMGRID_DB_URL` *or* `EXAMGRID_DB_HOST` / `_PORT` / `_NAME` | yes | Database location |
| `EXAMGRID_DB_USERNAME` / `EXAMGRID_DB_PASSWORD` | yes | Database credentials |
| `EXAMGRID_REDIS_URL` | yes | e.g. `redis://redis:6379` |
| `EXAMGRID_BOOTSTRAP_ADMIN_USERNAME` / `_PASSWORD` | first start | First exam-cell account on an empty database |
| `EXAMGRID_INSTITUTION_NAME` | no | Printed on hall tickets and charts |
| `EXAMGRID_REQUIRED_APPROVALS` | no | Default 2 |
| `EXAMGRID_RATE_LIMIT_PUBLIC` / `_LOGIN` | no | Requests per IP per minute (60 / 10) |
| `EXAMGRID_SCHEDULING_WORKER_THREADS` | no | Concurrent solves (2) |
| `EXAMGRID_DB_POOL_SIZE` | no | Database connections (10); also the ceiling for seat lookups while Redis is down |
| `EXAMGRID_TOKEN_TTL` | no | Token lifetime (8h) |
| `SPRINGDOC_APIDOCS_ENABLED` / `SPRINGDOC_SWAGGERUI_ENABLED` | no | Set to `false` to hide the API docs on a public deployment |
| `EXAMGRID_DEMO_ENABLED` | no | Seed the synthetic demo university into an empty database |
| `EXAMGRID_STORAGE_ROOT` | no | Defaults to `/data/storage` in the image |
| `API_UPSTREAM` (web image) | no | Where Nginx finds the API, default `api:8080` |

## Operations

- **Health:** `/actuator/health/readiness` (database) and `/actuator/health/liveness`; the web
  image answers `/healthz`.
- **Logs:** the API logs JSON (ECS) in the `prod` profile; every line and every audit entry
  carries the request id that Nginx forwards as `X-Request-Id`.
- **Metrics:** `/actuator/metrics` (exam-cell login required).
- **Redis outage:** seat lookups keep working from Postgres. After one failed call the API
  skips Redis for 10 seconds instead of waiting for timeouts, then probes again and refills
  the cache. Measured impact: [load test](benchmarks/load-test.md#losing-redis). Rate limiting
  is suspended (fails open) while Redis is down.
- **Load testing:** [`loadtest/`](../loadtest) has the k6 scripts used for the published numbers.
